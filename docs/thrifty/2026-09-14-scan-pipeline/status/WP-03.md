## Notes

Three bugs found and fixed this session, all in `pipeline/condition.py`:

1. The step 1/2 dispatcher called the combined load+fragment function once per
   requested step number, running it twice for `--through 2`. Fixed by caching the
   loaded MeshSet in the run context.
2. pymeshlab's decimation filters mutate the current mesh in place. Step 3 decimated
   the same MeshSet object step 5 later needed at full resolution, so a `--through 9`
   run wrote `chassis_scan_nofloor.ply` from an already-1M-face mesh instead of the
   true ~35M-face one. Fixed by decimating a duplicate mesh layer
   (`generate_copy_of_current_mesh`) and restoring the full-res mesh as current before
   returning.
3. Step 9's crop box used a Z range meant to represent height-above-floor and a Y
   range meant to represent left/right-of-symmetry-plane, but both were computed
   relative to the vehicle centroid instead of the floor and symmetry planes, and the
   X upper bound (`+800`) was an absolute centroid-relative coordinate rather than an
   offset from the rear-most percentile - together these captured almost the entire
   vehicle length instead of the rear slab, yielding 348-674 spurious cylinder
   candidates. Fixed by referencing Z to the floor plane, Y to the symmetry plane, and
   making the X window relative to the rear-most percentile on both ends.

After that fix the crop still passed 11-14 candidates through the spec's radius/
support/angle filter (near-duplicate re-detections of the two housings plus several
sub-segment fits of the connecting shaft between them, which is itself a cylinder
within the crop). Reported the full candidate table to the owner per the plan's step-9
stop condition; owner chose support-ranked dedup (recommended option). Implemented as:
partition the filtered candidates by sign of Y relative to the symmetry plane, keep
only the highest-support candidate on each side. Verified reproducible across two
independent CloudCompare RANSAC runs (candidate counts 426 and 467 respectively -
RANSAC has run-to-run noise) - the top-support candidate on each side was the same
physical housing both times, matching the reference to within 1.6mm in X before the
dedup fix, 0.10mm after.
