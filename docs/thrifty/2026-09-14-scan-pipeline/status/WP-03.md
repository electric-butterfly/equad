## Notes

Four bugs found and fixed this session, all in `pipeline/condition.py`:

1. The step 1/2 dispatcher called the combined load+fragment function once per
   requested step number, running it twice for `--through 2`. Fixed by caching the
   loaded MeshSet in the run context.
2. pymeshlab's decimation filters mutate the current mesh in place. Step 3 decimated
   the same MeshSet object step 5 later needed at full resolution, so a `--through 9`
   run wrote `chassis_scan_nofloor.ply` from an already-1M-face mesh instead of the
   true ~35M-face one (caught because `faces_before` in the step-5 log line read
   999999, not ~35M). Fixed by decimating a duplicate mesh layer
   (`generate_copy_of_current_mesh`) and restoring the full-res mesh as current before
   returning.
3. Step 9's crop box mixed frame references: Z and Y were meant to read as
   height-above-floor and left/right-of-symmetry-plane but were computed relative to
   the vehicle centroid instead, and the X upper bound (`+800`) was an absolute
   centroid-relative coordinate rather than an offset from the rear-most percentile -
   together these captured almost the entire vehicle length instead of the rear slab,
   yielding 348-674 spurious cylinder candidates instead of a tight rear-axle crop.
   Fixed by referencing Z to the floor plane, Y to the symmetry plane, and making the
   X window an offset from the rear-most percentile on both ends.
4. `datum.json`'s `rear_axle_housing` block reported the housing centres' raw
   scan-frame y/z and an X span computed from raw scan-frame coordinates, not the
   datum frame the rest of the file (and the reference) uses - values were off by
   hundreds of mm and didn't visibly correspond to the reference at all despite the
   underlying geometry being correct. Fixed by transforming the centres through
   `T_scan_to_datum` before reporting.

After fix 3, the crop still passed 11-14 candidates through the spec's radius/
support/angle filter (near-duplicate re-detections of the two housings plus several
sub-segment fits of the connecting shaft between them, itself a cylinder within the
crop). This is the plan's explicit step-9 stop condition (kept != 2); reported the
full candidate table to the owner rather than tuning silently. Owner chose
support-ranked dedup: partition the filtered candidates by sign of Y relative to the
symmetry plane, keep only the highest-support candidate on each side. Verified
reproducible across two independent CloudCompare RANSAC runs (candidate counts 426
and 467 - RANSAC has run-to-run noise) - the top-support candidate on each side was
the same physical housing both times, matching the reference to within 1.6mm in X
before the dedup fix, 0.10mm after.

No out-of-scope findings.
