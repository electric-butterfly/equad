One implementation note for whoever reads this code next, not an owner finding: build123d's
`Compound(children=...)` reparents child shapes into whichever Compound last claimed them, so
reusing a Compound's own `.children` to build a second Compound (e.g. box.step's parts plus the
cell block, for box-full.step) silently invalidates the first Compound's `.solids()`/`.volume`.
`enclosure.py` captures those numbers immediately after each `export_step()` call rather than
reading them back off the shape object afterwards.
